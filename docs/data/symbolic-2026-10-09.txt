MEANING OF A PASS
  Every check_ parameter is symbolic: Halmos covers every value of its type, not a sample.
  The call sequence is fixed per check (length and order below) and starts from the Base
  fixture: bodies L1 (v1) and L2 (v2), auditors AID_A under L1 and AID_B under L2, both
  added at START = 1790000000, accredited until 1924905600; time START + 1 h. A pass is
  "no input violates an assertion for this sequence", i.e. proved within these bounds; it
  is not a proof over all call sequences. Fixture addresses are concrete (see MODELLING).
  Loops: one fixed-length loop of 3 (check_P1_threeClaims), within --loop 3. "bounds: []"
  in every result: no loop or path bound was hit.

ATTEMPTS THAT DID NOT COMPLETE, AND MODELLING ERRORS FOUND (same day)
  1. Fixture addresses from makeAddr (vm.addr). Halmos models vm.addr as an uninterpreted
     function f_vmaddr(key), distinct from other vm.addr results but free to equal any other
     address (a deployed contract, a precompile). With these, a single P3 check over all
     events (13 symbolic inputs) reported 15 counterexamples in 649 s (stopped by hand), and
     check_P3_senderAuditorExpiry reported 2 (e.g. sender 0x4000…0 with AID_A, t = 0x70000000).
     We replayed two counterexamples of the first run concretely in forge (a temporary test
     calling the check with the reported values; v1 sending with AID_A, L1 not suspended):
     both passed. The others need a fixture address equal to the symbolic sender. Spurious:
     a modelling error, not a contract bug. Fix: HalmosPropertiesTest.setUp assigns
     concrete, distinct addresses (0xA00001…, 0xB00001…, 0xC00001…) before Base.setUp. With
     the fix all checks pass, and the mutation controls above show they can still fail.
  2. The single P3 check over all events (4 senders x rotation x suspension of L1 or L2 x
     lift x revocation of AID_A or AID_B, all times symbolic): no result after 11 minutes
     (1.3 GB), stopped. Replaced by the four P3 checks above, one per kind of event.
  3. check_P1_anyRegistrationThenClaim: the second registration with every input field
     symbolic (scope keys, report key, supersedes, supplier, ...) from any sender, then a
     claim with a symbolic report key: no result after 1202 s (watchdog), 4.7 GB resident.
     Symbolic keys into nested mappings make each storage read a case split over all
     written slots. Replaced by check_P1_secondRegistrationThenClaim (finite key choices).
